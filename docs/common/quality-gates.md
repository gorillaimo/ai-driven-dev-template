# Quality Gates

このドキュメントは、AI駆動開発で実装前・PR前に確認する品質ゲートを定義する。

すべてのissueで全項目を満たす必要はない。AIは変更内容に応じて該当するゲートを判定し、該当理由、確認結果、未確認事項をissueまたはPR本文に報告すること。

## 基本方針

- Quality Gatesは、機能が動くことだけで完了としないための確認観点である。
- 該当するゲートがある場合、AIは実装前に確認観点を提示し、人間の承認を得ること。
- High Risk issueでは、NFR / Security / Resiliency の該当有無を必ず確認すること。
- 確認できない項目は推測で埋めず、未確認事項または後続issue候補として明記すること。

## NFR Gate

### 該当する変更

- パフォーマンスに影響する画面、API、バッチ、非同期処理。
- 大量データ、ファイル、画像、一覧、検索、集計を扱う変更。
- 外部サービス呼び出し、ネットワーク通信、デバイス機能を含む変更。
- ユーザー体験、レスポンス時間、可用性、運用監視に影響する変更。

### 確認観点

- 想定ユーザー数、データ量、リクエスト量、利用頻度は明確か。
- レスポンスタイムや起動時間に影響する処理はあるか。
- タイムアウト、リトライ、キャンセル、エラー時挙動は決まっているか。
- ログ、メトリクス、トレース、アラートで問題を追跡できるか。
- モバイルでは通信失敗、低速回線、バックグラウンド復帰を考慮しているか。
- Lambdaなどサーバーレス実行基盤では、コールドスタート、タイムアウト、メモリ、同時実行を考慮しているか。

## Security Gate

### 該当する変更

- 認証、認可、ロール、アクセス制御。
- ユーザー情報、個人情報、機微情報、決済情報。
- API公開、外部連携、Webhook、ファイルアップロード。
- シークレット、環境変数、Infrastructure権限、IAM。
- ログ、監査、エラーレスポンスに機密情報が含まれ得る変更。

### 確認観点

- 認証済みユーザーだけが操作できるか。
- 他ユーザー、他テナント、他ロールのデータへアクセスできないか。
- 入力値検証、出力エスケープ、ファイル形式・サイズ制限はあるか。
- シークレットや認証情報をコード、ログ、PR本文に含めていないか。
- IAMやAPI権限は最小権限になっているか。
- エラーやログで機密情報を返していないか。
- セッション、トークン、Cookie、CORS、CSRFなど該当するWebセキュリティ観点を確認したか。

## Resiliency Gate

### 該当する変更

- AWSリソース、Infrastructure、デプロイ構成。
- 外部API、決済、メール、通知、ストレージ連携。
- 非同期処理、キュー、スケジュール実行、リトライ。
- データ保存、更新、削除、整合性が重要な処理。
- 障害時の復旧、再実行、ユーザー通知が必要な処理。

### 確認観点

- 外部API失敗時、タイムアウト時、レート制限時の挙動は決まっているか。
- リトライしてよい処理か。二重実行されても壊れないか。
- 部分失敗時にデータ不整合が起きないか。
- 障害や失敗をログ、メトリクス、アラートで検知できるか。
- 復旧手順、再実行手順、後続issue候補が明確か。
- ユーザーへ表示するエラー、通知、再試行導線が決まっているか。

## PR報告フォーマット

PR本文では、該当するゲートについて以下を記載する。

```md
## Quality Gates

- NFR: 該当なし / 確認済み / 未確認あり
- Security: 該当なし / 確認済み / 未確認あり
- Resiliency: 該当なし / 確認済み / 未確認あり

確認内容:
- TBD

未確認事項 / 後続issue候補:
- TBD
```
