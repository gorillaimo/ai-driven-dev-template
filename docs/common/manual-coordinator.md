# 担当を決める・引き継ぐ・作業の重複に対処する

**複数の人やAIで作業するときに、担当範囲と作業の順序を決めるための手順です。**
この調整を担当する人をCoordinatorと呼びます。専任の担当者を置く必要はなく、プロジェクトの責任者が兼ねることもできます。

## 1. いつ読めばよいか

AIから担当決めや引継ぎの判断を求められたら、該当する手順を確認してください。
1人の開発者と1つのAIでIssueを順番に進める場合は、最初から読む必要はありません。

| 状況 | 人間が決めること |
| :--- | :--- |
| 複数人・複数AIで作業を分担したい | 誰がどのIssue・ファイルを担当するか、どの作業を先にするか |
| 作業を別の人やAIへ引き継ぎたい | 現在の担当者がどこで作業を止め、誰が何を引き継ぐか |
| 複数の人やAIが同じ作業を始めた、記録と実際の状態に食い違いがある | 対象範囲への新規着手を止め、どの記録が正しく、どの作業を継続するか |
| 進捗の報告が途絶え、作業が続いているか分からない | 元の担当者に確認し、継続・保留・引継ぎのどれにするか |
| 調整する人を交代したい | 交代前の担当者が操作を止め、後任が記録と作業を引き継いだことを確認する |

参加者が増えたり、複数の作業を同時に進めるようになったりしたら、AIへ伝えてください。人間が1人でも、複数AIが同時に作業する場合は調整が必要になることがあります。

## 2. AIと人間で進める流れ

1. **AIが状況を整理する。** Issue・担当者・ブランチ・PR・着手記録・未反映の変更・必要な承認を調べ、確認できない点を示します。
2. **AIが案を示す。** 状況に応じて参照する箇所、担当者や作業順の推奨案、人間に決めてほしいことを短く提示します。
3. **人間が判断する。** 担当者が作業を引き受けているか、必要な権限があるか、現在どこまで進んでいるかを確認し、担当範囲や引継ぎ方法を確定します。
4. **決定内容を記録し、実際の状態を確認する。** AIに記録案の準備や確認の補助を任せられます。人間が操作を確定し、Issueに設定された担当者・着手記録・作業ブランチが、決定内容と一致していることを確認してから、許可された作業を進めます。

例えば、二つのIssueが同じ認証設定を変更する場合、AIが「先に一方を完了し、その結果を確認してから他方を進める」と提案します。
人間は、作業の順序とそれぞれの担当範囲を決めます。記録する項目は、AIが[詳細手順](manual-coordinator-reference.md)を参照して案内します。

## 3. 場面ごとの進め方

### 担当を決めて作業を始める

Issueに責任を持つ人間、実際に作業する人やAI、変更する範囲、他の作業との重複を確認します。
担当と着手記録を確定し、担当範囲・作業ブランチ・承認内容に食い違いがないことを確認してから始めます。
AIの提案や「着手できる」という検査結果だけでは、担当は確定しません。

→ [担当決めから着手までの詳細](manual-coordinator-reference.md#assignment)

### 作業を引き継ぐ

これまでの担当者による更新を止め、まだpushしていない変更を保存します。ブランチ・PR・残作業・承認の状況も記録して確認します。
引継ぎ先が作業と記録を受け取ったことを確認し、これまでの担当者の作業終了を着手記録に追記してから、新しい担当者の着手を確定します。
元の作業が止まったか分からないときは、同じ範囲で新しい作業を始めません。

→ [作業の終了・担当変更・調整担当の交代](manual-coordinator-reference.md#handoff)

### 重複・食い違い・更新失敗を直す

問題があるIssueや共有ファイルへの新規着手・割当を止め、元の記録を残したまま実際の状態と照合します。
「担当だけ変わった」「ブランチはあるが着手記録がない」「操作が成功したか不明」など、確認できたことと不明点を分けます。
人間が、継続するか、未完了の操作を補うか、取り消すか、保留するかを決め、更新後の状態を再確認してから再開します。問題と無関係で、状況を確認できている作業の着手記録まで一律に終了扱いにはしません。

→ [食い違いが起きたときの確認表](manual-coordinator-reference.md#reconciliation)

### 進捗が分からない作業を確認する

記録が古くても、担当者が作業をやめたとは限りません。本人に状況を確認し、ブランチ・PR・未反映の変更も調べます。
確認が取れるまで担当を変更したり、同じ作業を別の人やAIに始めさせたりしません。

→ [進捗確認・中断・再開の詳細](manual-coordinator-reference.md#updates)

## 4. 共通して守ること

- Issueに責任を持つ人間は1人にし、作業を行うAIの名前と区別します。
- 同じIssueや共有範囲の割当操作は同時に行わず、今回の操作担当を1人にします。
- 担当変更・終了・訂正は追記し、以前の記録を消しません。秘密情報や変更内容の差分そのものは、コメントに載せません。
- 古い記録、Issueのclose、PRのmergeだけで、着手終了や作業完了を決めません。Issueで合意した内容、検証結果、未反映の作業、作業終了の記録をそれぞれ確認します。
- 情報不足や操作失敗が残る対象では、新規割当・着手を保留します。復旧が難しい場合も元記録を残し、人間が作業の状況を照合し、従来のIssue中心の運用へ戻すか判断します。
