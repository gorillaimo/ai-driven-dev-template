# 担当決め・引継ぎ・作業の重複を調整する

**複数人や複数AIの作業を、「誰が、どこまで、いつ進めるか」整理するための手順です。**
この調整をする人をCoordinatorと呼びます。専任の役職を新設する必要はなく、人間の責任者が兼ねられます。

## 1. いつ読めばよいか

AIから担当や引継ぎの判断を求められたとき、今回の場面だけ確認します。
1人・1つのAIでIssueを順番に進める通常の運用では、最初から読む必要はありません。

| 起きたこと | 人間が決めること |
| :--- | :--- |
| 複数人・複数AIで作業を分担したい | 誰がどのIssue・ファイルを担当するか、どの作業を先にするか |
| 作業を別の人やAIへ引き継ぎたい | 旧担当がどこで止め、誰が何を受け取るか |
| 同じ作業に二人が着手した、記録と実際の状態が違う | 対象の新規作業を止め、どの記録と作業を引き継ぐか |
| 進捗確認が途絶え、続いているか分からない | 元の担当へ確認し、継続・保留・引継ぎのどれにするか |
| 調整する人を交代したい | 旧担当が操作を止め、新担当が引き継いだことを確認する |

参加者や並行作業が増えたらAIへ伝えてください。人間が1人でも、複数AIが同時に作業する場合は調整が必要になることがあります。

## 2. AIと人間で進める流れ

1. **AIが状況を整理する。** Issue・担当者・ブランチ・PR・着手記録・未反映の変更・必要な承認を調べ、確認できない点を示します。
2. **AIが案を示す。** 今回読む箇所、担当や作業順の推奨案、人間に決めてほしいことを短く提示します。
3. **人間が判断する。** 当事者の引受・権限・作業状況を確認し、担当範囲や引継ぎを確定します。
4. **決定と実際の状態を記録・確認する。** AIに記録案の準備や確認の補助を任せられます。人間が操作を確定し、Issueの担当・着手記録・ブランチ等の一致を確認してから、許可された作業を進めます。

例えば、二つのIssueが同じ認証設定を変更する場合、AIが「先に一方を完了し、その結果を確認してから他方を進める」と提案します。
人間は、その順序と担当範囲を判断します。具体的な記録項目は、AIが[詳細手順](manual-coordinator-reference.md)から案内します。

## 3. 場面ごとの進め方

### 担当を決めて作業を始める

Issueの責任を持つ人間、実際に作業する人やAI、変更する範囲、他の作業との重複を確認します。
担当と着手記録を確定し、作業ブランチ・必要な承認との一致を確認してから始めます。
AIの候補提示や「着手できる」という検査結果だけで担当は決まりません。

→ [担当決めから着手までの詳細](manual-coordinator-reference.md#assignment)

### 作業を引き継ぐ

旧担当の更新を止め、未pushの変更・ブランチ・PR・残作業・承認の状況を保存して確認します。
引継先が受け取ったことを確認し、旧担当の着手終了を記録してから、新しい担当の着手を確定します。
元の作業が止まったか分からないときは、同じ範囲で新しい作業を始めません。

→ [作業の終了・担当変更・調整担当の交代](manual-coordinator-reference.md#handoff)

### 重複・食い違い・更新失敗を直す

問題があるIssueや共有ファイルへの新規着手・割当を止め、元の記録を残したまま実状と照合します。
「担当だけ変わった」「ブランチはあるが着手記録がない」「操作が成功したか不明」など、確認できたことと不明点を分けます。
人間が継続・不足操作の補完・取消・保留を決め、結果を読み戻してから再開します。無関係で確認済みの作業まで一律に解除しません。

→ [食い違いが起きたときの確認表](manual-coordinator-reference.md#reconciliation)

### 進捗が分からない作業を確認する

記録が古くても、担当者が作業をやめたとは限りません。本人とブランチ・PR・未反映の変更を確認します。
確認が取れるまで担当を奪ったり、同じ作業を別の人やAIに始めさせたりしません。

→ [進捗確認・中断・再開の詳細](manual-coordinator-reference.md#updates)

## 4. 共通して守ること

- Issueの責任を持つ人間は1人にし、作業者のAI名と区別します。
- 同じIssueや共有範囲の割当操作は同時に行わず、今回の操作担当を1人にします。
- 担当変更・終了・訂正は追記し、以前の記録を消しません。秘密の値や生の差分はコメントに載せません。
- 古い記録、Issueのclose、PRのmergeだけで、着手終了や作業完了を決めません。契約・検証・未反映作業と終了記録を別に確認します。
- 情報不足や操作失敗が残る対象では、新規割当・着手を保留します。復旧が難しい場合も元記録を残し、人間が現在地を照合して運用を戻します。
