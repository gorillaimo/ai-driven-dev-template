# v2 運用マニュアル

**具体的な作業を指示することも、次に行う作業の判断をAIに任せることもできます。**
AIに任せたいときは「進めてください」と依頼できます。AIがIssue・コード・作業記録を調べて進捗を把握し、次に行う作業を選びます。人間は目的を決め、AIからの確認事項に答え、成果物をレビューします。
工程ごとの長いプロンプトや検査コマンドを覚える必要はありません。

## 1. 初回はセットアップから始める

**最初にAIへ送るプロンプトは、[初期セットアップ](operations-setup.md)に掲載しています。**

| 始めたいこと | 最初に使う依頼例 |
| :--- | :--- |
| 新規プロジェクトを始める | [新しいプロジェクト](operations-setup.md#new-project) |
| 既存プロジェクトへ初めて導入する | [既存プロジェクトへの導入](operations-setup.md#existing-project) |

初回のセットアップでは、プロジェクト全体で作りたいもの・目的・制約を伝えます。AIが必要なIssueの準備と全体要件・構成の整理を進めます。
準備中も、希望する作業や変更点を具体的に指示できます。AIから質問や承認の依頼があれば、その内容を確認して回答します。
セットアップ後はこのマニュアルを使います。初回用プロンプトを送り直す必要はありません。
現在はv2開発版です。採用する範囲や移行時の確認は[試用前の確認表](v2-adoption-checklist.md)にまとめています。

開発中のプロジェクトを新しい会話や別のAIへ引き継ぐ場合は、対象リポジトリ・目的・人間の担当者を伝え、「作業記録を確認して開発を引き継いでください」と依頼します。対応するIssueが決まっていれば、その番号も渡します。

## 2. Issueへの着手と作業の継続を依頼する

各Issueへの着手時には、AIがIssue本文から、そのIssueで達成したいことと作業範囲を確認します。本文に記載されていれば、対象Issueの番号を伝えるだけで依頼でき、毎回説明し直す必要はありません。
対象Issueが決まっていない場合も、AIに次の作業の選択を任せられます。AIは既存の担当・着手記録・承認状況を調べ、確認や調整が必要なら提案します。

| 場面 | 人間が伝えること | AIが行うこと |
| :--- | :--- | :--- |
| 対象Issueを指定したい | 「Issue #123に着手してください」 | Issue本文の目的・範囲と着手条件を確認する |
| 今回行う作業を具体的に指示したい | 「今回は設計だけ進めてください」 | 指定された範囲で進め、実装には入らない |
| 次に行う作業や進め方をAIに任せたい | 「進めてください」 | 進捗・残っている作業・承認状況から次の作業を選び、許可された範囲で進める |
| 提示された設計でよい | 「その設計で進めてください」 | 承認された範囲でテスト・実装・検証を進める |
| 方針を変えたい | 「○○に変更してください」 | 影響を確認し、Issue・計画・必要な文書を更新する |
| PRをマージした | 「マージしました。進めてください」 | マージ結果と最新mainを確認し、次の作業を整理する |
| 中断・再開したい | 「ここで中断してください」／「作業を再開してください」 | 作業記録を残す／記録と実際の状態を照合して再開する |

具体的な指示があれば、AIはその意図とIssueの範囲に合わせて進め方を調整します。次の作業をAIに任せることもできるため、人間が工程を毎回指定する必要はありません。
作業が止まる場合、AIは理由・必要な判断・次の一手を短く示します。

## 3. AIに任せること

- 最新の規約・Issue・PR・着手記録を読み、作業の重複や競合を確認する。
- 目的に沿って次の作業を選び、必要ならIssueの作成・整理、分割、担当や着手条件の確認を行う。
- 変更の大きさとリスクから、必要な調査・設計・検査と、人間へ確認する時点を判断する。
- 作業ブランチを用意し、要件・設計・必要なAPI定義を整え、テスト先行で実装・検証する。
- 変更内容、検証結果、未確認事項を記録し、レビューできるPRを用意する。

AIは[AGENTS.md](../../AGENTS.md)と[開発規約](development-rules.md)に従います。
担当者・`ready-for-ai`・承認が不足する場合は着手条件を整え、他の人やAIの作業がある場合は調整を求めます。
目的が曖昧なときや、次に進める作業が決められないときは、候補と確認点を提示します。

## 4. 人間が判断すること

**作るもの・優先順位・提案の妥当性・成果物を確認します。**
AIは、設計の承認、未決の仕様、権限や担当の調整、共通構成の変更について、判断に必要な情報と選択肢を添えて提示します。
承認するときは、何に同意するか分かる返答にします。単なる継続依頼を、まだ提示していない設計や次のIssueへの承認に読み替えません。

複数人・複数AIでの担当割当や引継ぎが必要になったら、AIが[担当調整の手順](manual-coordinator.md)から参照すべき箇所を選び、推奨案と人間が判断すべき点を示します。まずはIssueを1件ずつ進める運用から始められます。
マージ・本番反映・Releaseは、それぞれの対象と影響を確認して判断します。

## 5. PRを確認する

AIは、PRに「何を変えたか」「受け入れ条件を満たした根拠」「実行した検証」「残る課題」をまとめます。
人間は次を確認して、マージを判断します。

- 目的どおりに動き、Issueの範囲に収まっているか。
- 設計・画面・動作の変更が、意図した内容か。
- テストとCIの結果、未検証の範囲を受け入れられるか。
- 性能・安全性・障害時の復旧に関する確認が必要なら、その結果と残る懸念が明らかか。

詳しい確認が必要なときは[レビュー項目](operations-reference.md#人間側のレビュー観点)を参照します。
CI成功は判断材料です。仕様や実運用への適合も含めて人間がレビューします。

## 6. 止まったとき・引き継ぐとき

「何が止まっているか、次に何を判断すればよいか教えてください」と依頼します。
AIは元の記録を保ち、Issue・担当・ブランチ・PR・承認・未反映の作業を照合します。
記録が不足・破損している場合は、確認できたところから手動で現在地を整理し、必要な承認を取り直します。

人間がファイルを修正した場合や、別の人・AIへ引き継いだ場合は、その事実を伝えてください。
具体的な対処例は[トラブルシューティング](operations-reference.md#トラブルシューティング)、移行前の運用へ戻す方法は[移行ガイド](migration-v1-to-v2.md)にあります。

規約はAIが読む自然言語の指示です。検査ツールはNode.jsで実行し、計画や記録の矛盾を調べます。AIはその結果を使って作業を進めます。
Node.jsは開発管理用なので、開発するシステムの言語は問いません。テンプレート運用の検査と、作るアプリ自身のテストは別に行います。
Project用の台帳や高度な調整は、必要な範囲で追加できます。
