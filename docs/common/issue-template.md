## issue種別

該当するものを1つ残す。

- 通常の機能issue: 要件定義、設計、API定義、テスト、実装までを1つのissue/PRで扱う。
- 要件・設計issue: 不確実性が高いため、要件定義、設計、API方針までを先にレビューする。
- プロトタイプissue: 営業デモ、要件確認、画面遷移確認、技術検証のために動く試作品を作り、後続issueと要件・設計への反映事項を整理する。
- 実装issue: 承認済みの要件・設計に基づき、テストと実装を行う。
